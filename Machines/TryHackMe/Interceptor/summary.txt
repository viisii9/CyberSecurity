STEP 3 — RATE LIMIT BYPASS (X-Forwarded-For)
----------------------------------------------------------------
Problem:  "Too many login attempts" error after several tries.

Fix:      Server trusted IP from headers instead of TCP connection.

Headers to try:
  X-Forwarded-For: <ip>
  X-Real-IP: <ip>
  Client-IP: <ip>

  ip = f"{random.randint(1,223)}.{random.randint(0,255)}.{random.randint(0,255)}.{random.randint(1,254)}"

STEP 4 — OTP BYPASS (Parameter Pollution / Mass Assignment)
----------------------------------------------------------------
Problem:  6-digit OTP required, code unknown.

Vulnerability: Server read is_verified directly from POST body.

Fix:      Inject extra field in multipart request (Burp Repeater):

  Content-Disposition: form-data; name="is_verified"

  true
  ------WebKitFormBoundaryXXXX--

Lesson:   Server should NEVER trust client-supplied verification flags.
          Always compute state server-side.

STEP 5 — CLIENT-SIDE RESPONSE INTERCEPTION (Burp)
----------------------------------------------------------------
Vulnerability: JavaScript checked data.ok to decide login/redirect.
               Server state was separate from client state.

Technique:
  Burp -> Proxy -> Options -> Intercept Server Responses -> Enable
  Submit form -> Forward request -> Edit response:

Lesson:   Client-side checks are suggestions, not security.
          Always verify server-side session is actually authenticated.

----------------------------------------------------------------
KEY LESSONS LEARNED
----------------------------------------------------------------
1. Always check Content-Type — PHP ignores JSON body in $_POST
2. Check backup files: .bak, .old, .orig, ~, .swp
3. Rate limits often key off headers, not real IPs — rotate X-Forwarded-For
4. is_verified / role / admin fields in POST = mass assignment vuln
5. JavaScript-enforced controls = client-side only, bypass via Burp response intercept
6. 127.0.0.1 blocked? Try [::ffff:7f00:1] (IPv6-mapped), 127.1, decimal IP
7. file:// in SSRF = arbitrary file read (curl-based backends)
8. GD image re-encoding destroys polyglot shells — don't waste time on it
9. Database credentials in config.php often reused for phpMyAdmin
10. MySQL root + INTO OUTFILE = webshell if secure_file_priv is not restricted
